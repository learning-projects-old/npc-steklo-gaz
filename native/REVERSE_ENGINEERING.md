# Обратная разработка ТОК1

Дата исследования: 31 октября 2026 года. Объект: `E:\dev\apps\npc-steklo-gaz\ТОК1`.
Полный перечень 679 файлов с SHA-256 находится в `evidence/inventory.json`.

## Происхождение и состав

Это набор расчётных DOS-программ для электродных систем стекловаренных печей. Основной
пользовательский сценарий — PTOK в `TOKP.EXE`. В исходном `../dosbox-0.74-3.conf`, секция
`[autoexec]`, запускается `TOKP.exe`, а диск C монтируется из старого `C:\mp`.

Обнаружены два различных текста FORTRAN: `FOR/TOKS.FOR` (5013 байт) и `FOR/TOKPL.FOR`
(2801 байт), каждый повторяется в нескольких каталогах. Это листинги/перепечатки: присутствуют
номера строк, заголовки страниц `FORMAT IV V02.6 WED 20-DEC-89`, таблица размещения переменных,
ошибки `IF9nDAT`, `SH=E1+E2`, `A(20.20)`, нестыковки имён и аргументов. Их нельзя объявлять
готовым исходным проектом или просто отдать компилятору.

Исходников BASIC не найдено. В DOS EXE есть строка
`MS Run-Time Library - Copyright (c) 1989, Microsoft Corp`, собственные сообщения FORTRAN I/O,
математические таблицы и 16-битный MZ-заголовок. Это согласуется с Microsoft FORTRAN, но
точная версия компилятора и исходные ключи сборки не установлены.

| Компонент | Установленная роль и источник |
|---|---|
| TOKP.EXE | PTOK, круглые/плоские электроды, подбор мощностей; проверено исполнением |
| TOKP1.EXE | Вариант расчётчика; совпадение круглого и плоского контрольных случаев подтверждено |
| TOK.EXE во вложенной копии | Заданные комплексные напряжения; токи подтверждены эталонной проверкой |
| TOKGRP.EXE / TOKGRD.EXE | Графический вывод, ссылки на TOKGR.DAT и TOKGR.LST; строка «ГРАФОР ИПМ АН СССР, ВЕРСИЯ 4.0, 04.01.88» |
| PLOT6.EXE | Поле плотности мощности; строки PLOT6.DAT, IST.DAT, POLE.DAT, Y51X137.DAT, prn |
| UDSOPR*.XLS | Формулы извлечены из BIFF; 30 сохранённых ячеек совпали с переносом |

Каталоги BESCWET, CHRUSTAL, DEP, FRITTA, PITATEL, SPEZ, TARA, TARA2 содержат варианты геометрии
и электрических схем. Названия указывают на предметные категории; точный смысл каждого варианта
нужно определять по данным и схеме питания, а не по имени файла.

## Фактический поток PTOK

1. Выбор плоских электродов (`1`) либо круглых.
2. Чтение BOX.DAT либо CIRCLE.DAT. Пользователь исторически подменял этот файл нужным вариантом.
3. Выбор печати коэффициентов системы и сопротивлений.
4. При нулевых радиусах/длинах — их ручной ввод; для части плоских схем — перенумерация.
5. Построение сопротивлений и системы на N−1 независимых токов.
6. При недостающих уравнениях — ручные дополнительные условия соединения.
7. Решение двух систем для действительной и мнимой составляющих токов.
8. Итерационный подбор напряжений до допуска по мощности.
9. Вывод TOKA.LST и двоичного TOKGR.DAT для графической программы.

Современное приложение принимает DAT напрямую, показывает геометрию и токи и сохраняет JSON.

## Формат DAT

Разделители — пробелы/переводы строк; десятичная точка; кодировка CP866; возможен завершающий
DOS EOF `1A`. Строки важны для распознавания заголовка. Нельзя считать любой `.DAT` текстом:
например, TOKGR.DAT — двоичный.

### Круглые электроды, заданные мощности

```text
L H rho N radius electrode_length
u1 v1
... N координат
M
i1 j1 ... iM jM
relaxation power_tolerance NP
U01 P01 ... U0NP P0NP
NB NA
... NB строк: row component group coefficient
... NA строк: power_group voltage_group electrode component coefficient
```

Индексы единичные; component=1 означает действительную часть, 2 — мнимую.
Нулевые radius/electrode_length означают запрос индивидуальных значений.
Для плоских электродов заголовок: `L H width rho N N2 placement`, N2=2N,
далее координаты двух концов каждого электрода; хвост мощностей имеет тот же вид.

Вариант заданных напряжений: после количества M идут M записей `i j Re(U) Im(U)`,
хвост с группами мощностей отсутствует. TOKPL.DAT и PLOT6.DAT соответствуют этому
распознаваемому варианту, но пространственный расчёт PLOT6 этим не восстанавливается.

## Восстановление формул круглых электродов

Смещения далее относительны началу загружаемого MZ-образа, сегмент 0000. Размер заголовка EXE —
2048 байт. Функция POLER находится в `1983–1CFD`. Вызовы математической библиотеки:
`0329:1407 log`, `1417 sin`, `141D cos`, `142C sinh`, `1432 cosh`, `143C sqrt`.
Проверяемый листинг создаётся `disassemble.py` и хранится в `evidence/TOKP-round.asm`.

Для каждой координаты (u,v):

```text
a = π/L
B = cosh(aH)
p = sin(au) cosh(av) / B
q = cos(au) sinh(av) / B
S = p² + q²
x = p + p/S
y = q − q/S
d = (a/S) sqrt((S−1)² + 4q²) sqrt(S + cos(2au)/B²)
```

Для разных электродов i,j:

```text
Dminus = (xi−xj)² + (yi−yj)²
Dplus  = (xi−xj)² + (yi+yj)²
Rij = rho / (2π length_i) × ln[Dminus Dplus / (di·2ri·yi·dj·2rj·yj)]
Rii = 0
```

Критическая деталь: введённые радиусы в оригинальном PTOK **удваиваются** перед POLER.
Это видно в основном коде около `05F1–05FD` и подтверждено дампом common-сегмента:
входные 0.24 превратились в 0.48. Если пропустить этот шаг, сопротивления CIRCLE окажутся
около 0.130 вместо правильных 0.112. Правильность названия «радиус» с физической точки зрения
здесь не переосмысляется: перенос сохраняет фактическую арифметику оригинала.

При разных длинах матрица может оказаться несимметричной: в знаменателе length_i.
Симметризовать её без отдельного обоснования нельзя.

## Плоские электроды

Исходник `FOR/TOKPL.FOR` и функция `TOKP.EXE:1CFE` используют то же преобразование концов в x.
В машинном коде подтверждено `sinh`, поэтому ошибочная перепечатка `SH=E1+E2` не переносится.

Для концов L0,L1 и M0,M1:

```text
k = (xL0−xM1)(xL1−xM0) / [(xL0−xM0)(xL1−xM1)]
```

Если placement=1 и в паре первый электрод, k заменяется на 1−k. Далее берётся восьмой корень
из k при k≥0.5 либо из 1−k иначе, и `logarithm=ln((1+root)/(1−root))`.
Обычная ветвь при k≥0.5 даёт `rho·logarithm/(π·width)`, иначе `π·rho/(width·logarithm)`.
Специальная ветвь меняет эти два выражения местами. Диагональ нулевая.
Совпадающие концы, k вне (0,1) и особые точки — явные ошибки нового приложения.

## Токи и мощности

Общий баланс определяет последний ток: `I_N = −Σ I_k` для k=1..N−1, отдельно для Re/Im.
Для заданной пары (i,j) строка системы:

```text
A_row,k = (R_jk − R_ik − R_jN + R_iN) / 2
U_row,component = Σ coefficient × U0_group
```

Мощность группы и итерационная матрица по `TOKS.FOR`, строки листинга 0087–0105:

```text
P_group += AP × U0_source × I_electrode,component
DA_group,source += AP × I_electrode,component
residual = Ptarget − P
DA × correction = relaxation × residual
U0 += correction
```

Остановка: максимальная абсолютная невязка мощности не больше допуска DAT. DA не является
полным якобианом; замена на «исправленный Newton» изменила бы последовательность итераций.
Сохранён исходный алгоритм, добавлен предел 10000 итераций (настраиваемый до 100000).
Вместо неполных вызовов GELG/LARRAY применяется исключение Гаусса с выбором главного элемента
и проверкой вырожденности. Прямое восстановление отсутствующей реализации GELG не заявляется.

Условия соединения не выводятся из одного лишь геометрического положения электродов.
Генерация ΣI=0 по компонентам графа — отдельный режим, применимый только к изолированным
источникам и выбираемый пользователем. По умолчанию недостающие уравнения вызывают ошибку.

## Доказательства и пределы проверенности

- `evidence/inventory.json`: хеши всех 679 файлов, классификация и проверки DAT.
- `evidence/decoded/`: читабельные UTF-8-копии FORTRAN без изменения оригиналов.
- `evidence/binary-analysis.json` и `.asm`: константы, адреса и восстановленные инструкции.
- `oracle/MEMORY.BIN`: исследовательский дамп после POLER на копии EXE; первая часть — сообщения,
  затем DS длиной A250h и common-сегмент длиной 2BDCh. В common: R с 0320h, шаг столбца C8h;
  радиусы 2A3Ch; длины 2B04h; входные L=2BCCh, H=2A30h, rho=2A34h.
- `oracle/batch/*/TOKA.LST`: фактические эталоны оригинального DOS EXE на копиях DAT.
- `evidence/oracle_comparison.json`: независимая сверка этих эталонов с Python.

Дамп получен только на исследовательской копии: вместо перехода после POLER записан переход
к временному DOS WRITE в неиспользуемой для этого случая плоской ветви. Оригинальный TOKP.EXE
не изменён. Готовая Windows-программа не содержит DOS-машинного кода и не читает этот дамп.

Из 400 верхнеуровневых/категорийных кандидатов 375 распознаны как расчётные DAT, 25 имеют другой
формат, являются результатами или неполными данными. 120 из 375 рассчитываются без ручных
дополнений. Причины остальных записаны отдельно: в основном недостающие уравнения, ручные
размеры электродов, а также вырожденные/особые схемы и несходимость. Ошибки не замалчиваются.

## Пространственное поле PLOT6

Функция поля находится в PLOT6.EXE:1490–1D6C, сопротивлений — с 1D6D.
Инструмент `reverse_plot.py` сохраняет инструкции в `evidence/PLOT6-*.asm`.
Восстановлена сетка 51 поперечных × 137 продольных узлов: u от −L/2 до L/2,
v от 0 до H. К каждому узлу и электроду применяется конформное преобразование,
описанное выше. Для узла x,y и электрода xe,ye:

```text
dx = x − xe; dy− = y − ye; dy+ = y + ye
D− = dx² + dy−²; D+ = dx² + dy+²
Fx_component += I_component × dx / (2π length) × (1/D− + 1/D+)
Fy_component += I_component / (2π length) × (dy−/D− + dy+/D+)
density = 0.83 × rho × d² × Σ(Fx_component² + Fy_component²)
```

Особые правила оригинала сохранены. Если узел попадает внутрь преобразованного электрода
(расстояние ≤ radius×d_electrode), берётся собственное поле первого такого электрода:
`0.83×rho×|I|²/(π×length×2radius)²`, без добавления остальных источников.
Нижний центральный узел u=0,v=0 интерполируется по двум поперечным соседям.
Малое отрицательное значение под вторым корнем производной на границе обнуляется, как в EXE.

Напряжения PLOT6.DAT — RMS и фаза в градусах, а не Re/Im. Исходник вычисляет шесть мгновенных
значений за полупериод с шагом π/6, затем делит сумму квадратов на 6 и умножает на 0.83.
В Python использована точная аналитическая эквивалентность этой равномерной выборки: сумма
квадратов двух действующих комплексных составляющих. Коэффициент 0.83 не переосмысляется.

Три эталона (исходный, напряжения ×1.2, rho ×2) проверены по каждому из 20 961 узлов.
Максимальное нормированное отклонение `|Python−DOS|/max(|DOS|,1)` меньше 0.000012.
Исходный бинарный IST.DAT из архива в точности совпал с повторно полученным DOS-эталоном
(SHA-256 CE4A3DE59F25F143504D98C3442FEBB6CA9ACA0EA3C9658F98ACF53127DA0809).

## TOK, TOKP1, графические файлы и таблицы

TOKP1 совпал с переносом для CIRCLE и BOX. TOK с заданными Re/Im совпал по компонентам токов
с максимальным отклонением около 0.000062. Сохранённый TOK.EXE открывает UNIT 6 с пробельным
именем, поэтому контроль выполнен на копии с заменой единственного байта имени на `R`.
Численные инструкции и математические константы при этом не менялись; исходный файл сохранён.
Подготовка и свидетельство этой особенности находятся в `extended_oracle.py`.

TOKGR.DAT содержит N и M как INTEGER*4 little-endian, затем M действительных напряжений,
M мнимых, N действительных токов, N мнимых. IST.DAT содержит 6987 REAL*4 little-endian,
по 51 поперечному значению каждого продольного столбца. Оба формата читаются современной
программой; TOKGR и IST также экспортируются. POLE и Y51X137 экспортируются текстом,
CSV добавляет явные координаты. Сами DOS-экраны ГРАФОР заменены современными диаграммами.

Из обоих UDSOPR XLS извлечены BIFF-записи FORMULA. Формула одинакова:

```text
A = Na2O + K2O/2
rho = 10 ** (−1.508 + 0.0204A + (4836 − 128A)/(T + 273))
```

Константа 273 сохранена. Проверены 30 сохранённых значений (15 температур каждого XLS).
Доказательства — `evidence/workbooks.json`; перенос — `resistivity.py`.
Единицы результата автоматически не подставляются в PTOK: единицы геометрии вариантов DAT
не установлены и должны быть согласованы пользователем.

Таким образом, перенесены вычислительные сценарии всего обнаруженного комплекта.
Точное воспроизведение пикселей DOS-экранов и поток команд DOS-принтера заменены интерфейсом
и экспортом. Численная сверка контрольных случаев не доказывает эквивалентность абсолютно
всех возможных пользовательских схем; ошибки геометрии, ввода и сходимости проверяются явно.
